# 异步任务

异步任务（Async Task）用于把耗时代码——发送邮件、生成报表、推送消息等——从请求处理流程中剥离，交由独立的 Task Worker 进程执行，避免阻塞 Worker 响应请求。Viswoole 基于 Swoole Task 机制封装了任务管理器（TaskManager），提供主题注册、异步投递、可靠队列持久化（租约、自动重试、跨实例恢复）、有效期淘汰与同步等待结果等能力。

## 核心组件

| 组件 | 全限定名 | 职责 |
| --- | --- | --- |
| TaskManager | `Viswoole\Core\Server\Task\TaskManager` | 任务主题的注册、投递与分发 |
| TaskQueue | `Viswoole\Core\Server\Task\TaskQueue` | 持久化队列的受理、认领、租约与恢复边界 |
| TaskFailedQueue | `Viswoole\Core\Server\Task\TaskFailedQueue` | 失败任务的查询、重放与删除 |
| TaskQueueQuery | `Viswoole\Core\Server\Task\TaskQueueQuery` | 持久化任务的只读元数据查询 |
| TaskQuarantinedQueue | `Viswoole\Core\Server\Task\TaskQuarantinedQueue` | 损坏记录的只读快照查询 |
| TaskProxy | `Viswoole\Core\Server\Task\TaskProxy` | 任务代理对象，作为处理器入参 |
| Task 门面 | `Viswoole\Core\Facade\Task` | 静态代理 TaskManager 的核心方法 |
| TaskService | `Viswoole\Core\Service\TaskService` | 任务服务提供者，负责装载任务管理器 |

`TaskService` 已在框架默认 `config/app.php` 的 `services[]` 中注册，任务能力开箱即用。业务代码统一通过 `Task` 门面调用：

```php
use Viswoole\Core\Facade\Task;

Task::register('email', SendEmailTask::class);      // 注册任务主题
Task::emit('email.notify', $data);                  // 异步投递，立即返回
$result = Task::emitWait('email.send', $data, 0.5); // 同步等待结果
```

## 前置配置

任务能力要求服务配置中 `Constant::OPTION_TASK_WORKER_NUM` 大于 0（任务进程数量，0 表示不开启）。框架默认 `config/server.php` 已按 CPU 核数开启任务进程，一般无需修改：

```php
// config/server.php
use Swoole\Constant;

return [
  'servers' => [
    'http' => [
      // ...
      'options' => [
        // 任务进程数量，0 表示不开启任务能力
        Constant::OPTION_TASK_WORKER_NUM => swoole_cpu_num(),
      ],
    ],
  ],
];
```

框架在合并服务配置时会强制开启 `Constant::OPTION_TASK_ENABLE_COROUTINE`（任务协程化），无需手动配置。

::: warning:不要自行注册 onTask 事件
框架的任务管理器在实例化时已经通过 ServerEventHook 注册了 `task` 事件分发器，请勿再通过 `ServerEventHook::addEvent('task', ...)` 或配置文件注册同名的 `task` 处理器：

- Swoole 对同一事件重复注册时会**覆盖**前一次设置，自行注册会替换框架的任务分发器，导致任务系统整体失效；
- Swoole 全部服务端事件中仅 `onTask` 的返回值有语义（将任务结果回传给 Worker 进程），即使多个处理器共存，也只有最后一个处理器的返回值生效，会破坏 `emitWait()` 的同步等待结果。

任务的业务逻辑一律通过 `Task::register()` 注册主题实现。详见 [生命周期钩子](2.lifecycle-hooks.md)。
:::

## 注册任务

任务按「主题（Topic）」组织：投递时指定主题名，框架将任务分发给该主题注册的处理器。主题名不区分大小写。

### 注册单个主题（回调方式）

```php
use Viswoole\Core\Facade\Task;
use Viswoole\Core\Server\Task\TaskProxy;

Task::register('email.send', function (TaskProxy $task, \Swoole\Server $server): void {
  $data = $task->data; // 投递时传入的业务数据

  // ...执行发送邮件逻辑
  $messageId = sendMail($data['to'], $data['subject'], $data['body']);

  // 回传结果给 Worker 进程（配合 emitWait 使用）
  $task->finish(['ok' => true, 'message_id' => $messageId]);
});
```

### 注册类批量注册

`register()` 的第二个参数传入类名时，框架通过反射扫描该类的全部公开方法，以 **「主题前缀.方法名」** 的格式批量注册：

```php
namespace App\Task;

use Viswoole\Core\Server\Task\TaskProxy;

class SendEmailTask
{
  /**
   * 异步通知：投递后立即返回，无需回传结果
   */
  public function notify(TaskProxy $task): void
  {
    // ...发送通知邮件
  }

  /**
   * 同步等待场景：必须 return 结果，否则调用方会阻塞到超时
   */
  public function send(TaskProxy $task): array
  {
    // ...发送邮件并返回结果
    return ['ok' => true, 'message_id' => '20260912001'];
  }
}
```

```php
// 注册后生成 email.notify、email.send 两个主题
Task::register('email', \App\Task\SendEmailTask::class);

// 投递
Task::emit('email.notify', ['to' => 'user@example.com']);
```

注册规则：

- 静态方法注册回调为 `ClassName::methodName`，实例方法注册为 `[ClassName, 'methodName']`；
- 以 `__` 开头的魔术方法（如 `__construct`）会被过滤，不会注册为主题；
- 同一主题重复注册时，后注册的处理器覆盖先注册的。

### 注册时机

任务主题映射保存在各进程的内存中。请在**服务启动阶段**注册——例如服务提供者的 `register()` / `boot()` 中，或监听 `AppInitialized` 事件——确保投递任务的 Worker 进程与执行任务的 Task Worker 进程都持有主题映射。参见 [服务提供者](3.service-provider.md)。

## 异步投递：emit()

`emit()` 投递任务后立即返回，不等待执行结果，是最常用的投递方式：

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `$topic` | string | 无 | 已注册的任务主题名称，未注册时抛出 `InvalidArgumentException` |
| `$data` | mixed | 无 | 传递给处理器的业务数据 |
| `$queue` | bool | `true` | 是否持久化到可靠队列，启用后崩溃、停机、投递失败均可自动恢复 |

返回值与异常按受理方式区分：

| 场景 | 结果 |
| --- | --- |
| `$queue = true` 受理成功 | 返回稳定的队列 ID（string），可用于[元数据查询](#任务元数据查询)与失败排查 |
| `$queue = true` 服务停机中 | 返回 `false`（明确拒收） |
| `$queue = true` 存储回执未知 | 抛出 `TaskAcceptanceUnknownException`（任务可能已受理，**禁止盲目补发**） |
| `$queue = false` | 返回 Swoole 任务 ID（int），拒收或投递失败返回 `false` |

```php
use Viswoole\Core\Facade\Task;

// 默认持久化：受理后返回队列 ID（string）
$queueId = Task::emit('email.notify', [
  'to'      => 'user@example.com',
  'subject' => '欢迎注册',
]);

// 明确不持久化的临时任务（服务重启后丢失），返回 Swoole 任务 ID（int）
$taskId = Task::emit('cleanup', ['type' => 'temp'], queue: false);
```

### 可靠队列：受理、租约与恢复

`$queue = true`（默认）时，任务先经**原子受理**写入缓存队列并拿到队列 ID，框架随后尽力完成首次投递。受理即框架接管恢复责任：受理成功后，即使首次投递失败、进程崩溃或整实例宕机，任务也不会丢失。

持久化任务在存储中按状态流转（`Viswoole\Core\Server\Task\TaskQueueState`）：

```
dispatched（已受理待投递）
   → running（被认领执行中，持有效租约）
       → ACK 成功：从队列删除
       → 失败/租约到期：retry（退避等待重投）→ 重新进入 running
       → 重试次数耗尽：failed（进入失败队列，停止自动重试）
```

核心机制：

- **原子认领**：Task Worker 消费前通过比较交换（CAS）+ 租约令牌认领任务，防止多实例重复执行同一任务；
- **租约与自动续期**：认领后获得 `task.lease_seconds` 时长的执行租约，运行期间每约 1/3 周期自动续期；处理器也可通过 `$task->renewLease()` 主动续期；
- **失败重试**：处理器抛出异常、投递失败或执行租约到期时，任务按指数退避（`task.retry`，带随机抖动）延迟后重新投递，次数包含首次执行；
- **ACK 才删除**：任务执行成功并确认提交后才从队列移除，与 `finish()` 回传结果无关；
- **跨实例恢复**：workerId 为 0 的 Worker 进程每秒扫描一次到期任务（投递租约到期、重试时间到点），可接管**任意实例**（包括已下线的旧实例分组）遗留的任务。

::: warning:至少一次语义要求处理器幂等
可靠队列是 **at-least-once** 投递语义：任务至少执行一次，但**可能重复执行**。典型场景是任务已执行完成但 ACK 提交前进程崩溃（如 `kill -9`），租约到期后恢复扫描会重新投递同一任务。处理器必须设计为幂等，或通过业务唯一键在业务侧去重。
:::

::: warning:持久化队列仅支持 Redis
可靠队列要求缓存驱动支持任务状态与索引的原子条件提交（`QueueStoreInterface`），内置驱动中仅 Redis 支持。默认通道为 File 时必须通过 `task.store` 指定 Redis 商店，否则首次使用持久化队列时抛出 `RuntimeException`。非持久化任务（`queue: false`）不受此限制。
:::

### 任务有效期

验证码短信等任务具有时效性，恢复执行的过期任务只会浪费资源甚至产生副作用。任务有效期用于在**消费时**淘汰过期任务，在 `config/task.php` 中配置：

| 配置键 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `store` | string\|null | `null` | 任务队列持久化使用的缓存商店名称，需在 `config/cache.php` 的 `stores` 中定义；持久化队列要求该商店支持原子条件提交（仅 Redis），`null` 表示跟随 `cache.default` 默认通道 |
| `instance_id` | string\|null | `null` | 稳定且唯一的部署实例 ID；未指定时每次启动随机生成。恢复扫描会接管同商店内所有实例分组的任务 |
| `lease_seconds` | int | `30` | 投递与执行租约（秒），运行期间自动续租；租约过短会放大重复投递窗口，建议不低于 10 |
| `retry.max_attempts` | int | `5` | 最大执行次数（包含首次执行），耗尽后进入失败队列 |
| `retry.base_seconds` | int | `5` | 首次失败的指数退避基数（秒），之后逐次翻倍 |
| `retry.max_seconds` | int | `300` | 退避等待上限（秒） |
| `expire` | int\|null | `null` | 全局默认有效期（秒），从投递时刻起算；`0` 或 `null` 表示长期有效 |
| `topics` | array<string, int\|null> | `[]` | 按主题覆盖有效期（秒），优先级高于 `expire`，主题名不区分大小写；值为 `null` 表示该主题豁免（长期有效） |

```php
// config/task.php
return [
  // 队列要求原子条件提交，内置驱动中仅 Redis 支持
  'store' => env('task.store'),

  // 稳定且唯一的部署实例 ID；未指定时每次启动随机生成
  'instance_id' => env('task.instance_id'),

  // 投递与执行租约（秒），运行期间自动续租；建议不低于 10
  'lease_seconds' => 30,

  // 失败重试：次数包含首次执行，投递失败不消耗次数
  'retry' => [
    'max_attempts' => 5,
    'base_seconds' => 5,
    'max_seconds'  => 300,
  ],

  // 全局默认有效期（秒）
  'expire' => env('task.expire'),

  // 按主题覆盖，优先级高于 expire
  'topics' => [
    'email.sendLoginCode' => 300, // 验证码任务 5 分钟有效
    'report.generate'     => 3600,
    'log.write'           => null, // 日志任务永不过期
  ],
];
```

生效机制：

- 有效期在 `emit()` 投递时按主题解析（`task.topics` 优先于 `task.expire`），随任务数据一起持久化；
- 任务被消费时检测有效期，已过期的**持久化任务**不执行处理器，直接进入[失败队列](#失败队列管理)（不静默丢弃，可人工重放或删除），并向 Worker 进程返回 `false`；非持久化任务过期时直接返回 `false`；
- 仅对 `emit()` 投递的任务生效；`emitWait()` / `emitsWait()` 为同步执行，不受此配置影响。

::: warning:商店名称必须已定义
`store` 指向的商店必须已在 `cache.stores` 中定义，否则首次使用任务队列时会抛出 `CacheErrorException`（快速失败）。切换商店前残留在旧商店中的队列条目不会被新商店恢复，切换时请确保队列已清空。缓存商店配置见 [缓存驱动](../6.cache/2.drivers.md)。
:::

## 同步等待结果：emitWait()

`emitWait()` 投递任务并阻塞等待执行结果，处理器通过 `finish()` 或 `return` 回传的数据**类型原样透传**：

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `$topic` | string | 无 | 已注册的任务主题名称 |
| `$data` | mixed | 无 | 传递给处理器的业务数据 |
| `$timeout` | float | `0.5` | 等待超时时间（秒） |

返回值：处理器回传的原始结果；主题未注册时抛出 `InvalidArgumentException`；超时或投递失败返回 `false`。

```php
$result = Task::emitWait('email.send', ['to' => 'user@example.com'], 3.0);

if ($result !== false) {
  // $result 为处理器回传的数据，可能是数组、字符串等任意类型
} else {
  // 超时、投递失败，或处理器回传了 false
}
```

::: warning:处理器必须显式回传结果
以下为 Swoole `taskwait` 的实测语义，编写处理器时务必注意：

| 处理器行为 | emitWait 结果 |
| --- | --- |
| `finish($data)` / `return $data`（非 false/null） | 立即返回 `$data`，类型原样保留 |
| `finish(null)` | 立即返回 `null`（null 作为真实结果送达） |
| `return false` / `finish(false)` | 立即返回 `false`，**与超时的 false 无法区分** |
| 无返回值 / `return null` | **阻塞满整个超时时间后**返回 `false`（性能陷阱） |
| 任务超时 / 投递失败 | 等待满超时后返回 `false` |

因此：处理器必须显式回传结果，无返回值会导致调用方白白阻塞整个超时时长；表达「业务失败」时应回传结构化数据（如 `['ok' => false]`）而非裸 `false` / `null`。
:::

### 并发等待：emitsWait()

同时投递多个任务并等待全部完成：

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `$tasks` | array<string, mixed> | 无 | 任务列表，键为主题名称，值为业务数据 |
| `$timeout` | float | `0.5` | 等待超时时间（秒） |
| `$isCo` | bool | `false` | `true` 使用协程并发调度（taskCo），`false` 使用 taskWaitMulti |

返回值：各任务的执行结果列表，超时未完成的任务对应位置为 `false`。

```php
$results = Task::emitsWait([
  'email.send'   => ['to' => 'user@example.com'],
  'report.build' => ['user_id' => 100],
], timeout: 3.0, isCo: true);
```

## 失败队列管理

持久化任务在以下情况进入失败队列：重试次数耗尽（超过 `retry.max_attempts`）、消费时校验失败（主题未注册或任务已过期，直接终态）。失败记录**永久保留**，不会自动清理，通过 `Task::failedQueue()` 获取管理入口（`Viswoole\Core\Server\Task\TaskFailedQueue`）人工处理：

```php
use Viswoole\Core\Facade\Task;

$failed = Task::failedQueue();

$list = $failed->list(page: 1, pageSize: 20); // 按任务 ID 排序的分页列表（pageSize 上限 100）
$record = $failed->get('队列 ID');            // 单条失败记录（含 lastError、attempts、failedAt），不存在返回 null
$newId = $failed->retry('队列 ID');           // 重放：原子生成新任务重新投递，并发冲突返回 false
$failed->delete('队列 ID');                   // 原子删除失败记录
```

行为要点：

- `retry()` 会生成**全新任务**（新队列 ID，执行次数清零，有效期重新起算），并以原记录当前状态为条件原子提交——并发重放时只有一个胜者，其余返回 `false`；
- 失败记录包含完整的任务元数据与最后一次失败原因（`lastError`），供定位问题；
- 分页按任务 ID 稳定排序，但并发变动时不提供快照保证。

## 任务元数据查询

通过 `Task::queue()` 获取同商店的只读元数据查询入口（`Viswoole\Core\Server\Task\TaskQueueQuery`），用于运维观测、排查堆积与定位卡死任务：

```php
use Viswoole\Core\Facade\Task;
use Viswoole\Core\Server\Task\{TaskQueueFilter, TaskQueueState};

$query = Task::queue();

// 筛选条件全部按 AND 组合；主题不区分大小写，实例 ID 精确匹配
$filter = new TaskQueueFilter([
  'topic' => 'email.notify',
  'state' => TaskQueueState::Retry,
]);

// 游标分页：isComplete 为 false 或 errors 非空表示存在损坏记录，结果非完整快照
$page = $query->list($filter, cursor: '', limit: 20);
// $page = ['list' => [...], 'cursor' => '下一页游标（空字符串表示扫描结束）', 'errors' => [...], 'isComplete' => true]

// 按状态统计任务数量
$stats = $query->count($filter);
// $stats = ['total' => 10, 'dispatched' => 2, 'running' => 3, 'retry' => 4, 'failed' => 1, 'errors' => [...], 'isComplete' => true]

// 查看单条任务详情（不含业务载荷与执行令牌）
$detail = $query->get('队列 ID'); // 已 ACK、删除或隔离时返回 null
```

可用的筛选字段（`TaskQueueFilter` 构造参数）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `topic` | string | 任务主题，不区分大小写 |
| `state` | TaskQueueState | 状态枚举：`Dispatched` / `Running` / `Retry` / `Failed` |
| `producerInstanceId` | string | 投递实例 ID |
| `executionInstanceId` | string | 执行实例 ID |

元数据主要字段：`queueId`（队列 ID）、`topic`（主题）、`state`（状态）、`attempts`（已执行次数）、`expire`（有效期秒数）、`dispatch_time`（投递时间戳）、`producerInstanceId`（投递实例）、`executionInstanceId` / `executionWorkerId`（执行实例与 Worker）、`leaseUntil`（租约到期）、`retryAt`（下次重试时间）、`failedAt`（失败时间）、`lastError`（最后一次失败原因）、`executionLeaseExpired`（执行租约是否已过期）。

查询边界：

- 默认查询同商店**全部实例**的任务，可按投递/执行实例筛选；
- `running` 且租约已过期的任务，`executionLeaseExpired` 为 `true` 且执行归属字段置空（不把失效消费者显示为仍在执行）；
- 游标分页每次最多扫描 1000 条索引，`cursor` 非空时须继续翻页；`count()` 的总数在并发变化与存在损坏记录时非精确值；
- 查询不恢复业务对象，仅返回元数据投影。

## 损坏记录隔离

恢复扫描发现无法解析的记录（存储数据损坏、载荷协议不兼容等）时，框架将原始字节移入隔离区，单条损坏不会阻塞其他任务的恢复。隔离记录只读保留，供人工定位协议或存储问题：

```php
use Viswoole\Core\Facade\Task;

$quarantined = Task::quarantinedQueue();

$records = $quarantined->list(page: 1, pageSize: 20);
// 每条记录：['queueId' => 队列 ID, 'raw' => 原始字节快照, 'reason' => 隔离原因, 'quarantinedAt' => 隔离时间]
$record = $quarantined->get('队列 ID'); // 不存在返回 null
```

::: info:隔离区不会自动处理
框架不会自动重放或删除隔离记录，`raw` 保留损坏时的原始字节以便取证。排查修复后，如业务仍需要该任务，请在业务侧按原参数重新投递。
:::

## 编写任务处理器

### 处理器签名

处理器的统一签名为 `function (TaskProxy $task, \Swoole\Server $server)`，第二个参数为 Swoole 服务实例，一般无需使用：

```php
function (TaskProxy $task, \Swoole\Server $server): mixed {}
```

### TaskProxy 属性与方法

| 成员 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `data` | mixed | `null` | 投递时传入的业务数据 |
| `topic` | string | 无 | 任务主题名称 |
| `queue_id` | string\|null | `null` | 队列唯一标识，非队列任务为 `null` |
| `renewLease()` | 方法 | — | 主动延长当前执行租约，失去执行权（租约被接管）或非持久化任务返回 `false` |

除上述成员外，TaskProxy 还通过 `__get` 代理访问 Swoole 原生 Task 对象的属性，如 `id`（任务 ID）、`worker_id`（所在 Worker 进程 ID）、`dispatch_time`（投递时间戳）、`flags`（标志位）；访问不存在的属性会抛出异常。

耗时的持久化任务建议在执行过程中主动续租，避免租约到期后被其他实例接管、重复执行：

```php
Task::register('report.build', function (TaskProxy $task): void {
  // ...第一阶段处理
  $task->renewLease(); // 主动续租，防止长任务租约到期被接管
  // ...第二阶段处理
});
```

### 回传结果：return 与 finish()

**方式一：处理器 `return`**——返回值经框架原样透传给 Worker 进程（触发 `onFinish` 事件或 `taskwait` 返回）。返回 `null`（含 void 处理器）不会触发结果投递，异步任务（配合 `emit()`）通常直接用这种方式：

```php
Task::register('email.query', function (TaskProxy $task): array {
  return ['id' => $task->data['id'], 'status' => 'sent'];
});
```

**方式二：调用 `finish(mixed $data): bool`**——通过 `__call` 直接透传给底层 Swoole Task 对象，遵循 Swoole 语义可以在任务处理器中**多次调用**，向 Worker 进程发送多个处理结果（流式任务可逐步回传中间结果）：

```php
Task::register('report.build', function (TaskProxy $task): void {
  $task->finish(['progress' => 50]); // 中间进度
  // ...继续计算
  $task->finish(['progress' => 100]); // 最终结果
});
```

注意：队列条目的清理发生在任务执行成功并 **ACK 提交后**，与 `finish()` 无关——`finish()` 只负责结果回传。

### 异常处理

框架在任务分发时已对 `Throwable` 做兜底：处理器抛出的异常会被捕获并记录到任务日志通道（含主题、队列 ID、异常原文和任务数据），同时向 Worker 进程返回 `false`（`emitWait` 调用方立即收到失败信号而不是干等超时），不会导致 Task Worker 进程崩溃。

持久化任务在框架兜底之外还会进入**重试流程**：按 `task.retry` 的指数退避策略延迟后重新投递，重试次数耗尽后进入失败队列等待人工处理。

业务层面仍建议自行捕获异常并回传结构化结果——裸 `false` 无法与超时/过期区分：

```php
Task::register('email.risky', function (TaskProxy $task): void {
  try {
    $result = doSomethingRisky($task->data);
    $task->finish(['ok' => true, 'data' => $result]);
  } catch (\Throwable $e) {
    $task->finish(['ok' => false, 'error' => $e->getMessage()]);
  }
});
```

### 数据序列化

跨进程传输大数据时，可使用 TaskProxy 的静态方法手动序列化/反序列化：

```php
$packed = TaskProxy::pack($largeData);  // 序列化为二进制字符串，失败返回 false
$data   = TaskProxy::unpack($packed);   // 反序列化，失败返回 false
```

## 完整示例

控制器中注册用户后异步发送欢迎邮件，不阻塞响应：

```php
use Viswoole\Core\Facade\Task;
use Viswoole\HttpServer\AutoInject\InjectPost;
use Viswoole\Router\Annotation\{Controller, RouteMapping};

#[Controller(prefix: 'user')]
class UserController
{
  #[RouteMapping(method: 'POST', title: '注册用户')]
  public function register(#[InjectPost] string $email): array
  {
    // ...创建用户

    // 异步发送欢迎邮件（queue 默认 true，受理后由框架保证最终执行）
    $queueId = Task::emit('email.notify', [
      'to'      => $email,
      'subject' => '欢迎注册',
    ]);

    return ['message' => '注册成功，确认邮件稍后送达'];
  }
}
```

## 最佳实践

1. **处理器必须幂等**：可靠队列是 at-least-once 语义，任务可能因租约到期、ACK 前崩溃等场景被重复投递，处理器应幂等设计或按业务唯一键去重。
2. **任务数据不宜过大**：建议控制在 2MB 以内（与服务配置 `OPTION_PACKAGE_MAX_LENGTH` 一致），大内容只传标识符，由处理器自行从数据库、缓存或文件系统加载。
3. **同步等待慎用**：`emitWait()` 会阻塞当前协程直到结果返回或超时，适合轻量查询型任务；耗时任务用 `emit()` 投递后通过缓存、数据库或其他渠道通知结果。
4. **超时时间按任务实际耗时设置**：`emitWait()` 的默认 0.5 秒仅适合快速任务，慢任务请显式传入更大的超时值。
5. **失败表达结构化**：回传 `['ok' => false, 'error' => '...']`，避免裸 `false` / `null` 与超时信号混淆。
6. **重要任务用 Redis 通道并设置合理租约**：持久化队列仅支持 Redis；`lease_seconds` 建议不低于 10，任务实际耗时超过租约时在处理器内调用 `renewLease()` 主动续期。
