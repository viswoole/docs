# 隐私与采集预算

慢请求快照会包含请求参数、响应正文和操作明细，天然接触业务数据。框架在设计上遵循「**默认最小暴露**」原则：隐私配置将「是否采集分组」与「隐藏业务字段」分开，敏感字段精确匹配脱敏、SQL 默认只存摘要、绑定值默认隐藏、所有正文与明细都有硬性字节/条数预算。隐私设置不会改变真实请求或响应。

## 隐私配置（privacy）

`monitor.privacy` 是唯一的隐私配置入口，由两部分组成：

- **`defaults`**：按「方向 × 分组」设置的全局默认；
- **`rules`**：按请求路径（可选限定方法）追加的规则。

```php
// config/monitor.php
'privacy' => [
  'defaults' => [
    'request' => [
      'body'    => ['capture' => true, 'redact_fields' => ['phone']], // 包含 post 副本
      'query'   => ['capture' => true, 'redact_fields' => ['phone']],
      'headers' => ['capture' => true, 'redact_fields' => []],
    ],
    'response' => [
      'body'    => ['capture' => true, 'redact_fields' => ['phone']],
      'headers' => ['capture' => true, 'redact_fields' => []],
    ],
  ],
  // paths 必填且非空，methods 省略表示全部方法；方向与分组独立
  'rules' => [
    // 精确路径：PUT /admin/auth/profile/phone 的请求正文额外脱敏验证码字段
    ['paths' => ['/admin/auth/profile/phone'], 'methods' => ['PUT'],
      'request' => ['body' => ['redact_fields' => ['code', 'oldCode']]]],
    // 通配路径：该组接口不采集请求/响应正文与查询参数
    ['paths' => ['/admin/service-configs/*'],
      'request'  => ['body' => ['capture' => false], 'query' => ['capture' => false]],
      'response' => ['body' => ['capture' => false]]],
  ],
],
```

### 分组

| 分组 | 作用 |
| --- | --- |
| `request.body` | 原始请求正文，`post` 副本共用此策略 |
| `request.query` | 查询参数 |
| `request.headers` | 请求标头 |
| `response.body` | 响应正文（含自定义裁剪摘要） |
| `response.headers` | 响应标头 |
| `request.metadata` | 方法、路径、路由参数等请求元信息，仅支持 `redact_fields` |
| `response.metadata` | HTTP 状态、完成标记等响应元信息，仅支持 `redact_fields` |
| `operation.metadata` | 数据库、缓存等操作记录，仅支持 `redact_fields` |

`metadata` 分组不允许关闭采集（`capture` 无效），只能隐藏其中命名字段的值——方法、路径、状态码等基础元信息始终保留。隐藏敏感路由参数时，日志展示路径也会整体脱敏，但不影响真实分发。

### 字段匹配：精确而非猜测

`redact_fields` 对分组内的字段名做**递归完全匹配**，匹配前统一归一化：

- 忽略大小写、下划线、连字符与首尾空白：`oldCode`、`old_code`、`old-code` 视为同一字段；
- **完全匹配，不做子串猜测**：`code` 不匹配 `business_code`；`redact_fields: ['body']` 只隐藏业务数据中名为 `body` 的字段，不会关闭正文容器；
- PDO 绑定参数的前导冒号自动去除，`:password` 与 `password` 命中同一规则。

::: warning:从旧配置迁移
`monitor.sensitive_keys` 与 `monitor.sensitive_keys_by_path` 已移除——即使配置为空数组，服务启动时也会直接报错，禁止新旧规则并存。旧全局字段分别放入需要保护方向与分组的 `defaults.*.*.redact_fields`；旧路径映射改写为 `rules` 列表；旧的 body 整组隐藏替换为 `request.body.capture => false`。旧子串机制覆盖过的高频复合变体（`confirm_password`、`auth_token`、`x-token`、`secret_key` 等）已内置，其余业务凭据字段必须显式配置完整名称。
:::

### 合并与匹配语义

- 内置保护、`defaults` 与**全部命中的** `rules` 取并集，不依赖规则书写顺序；
- `capture=false` 具有**否决权**：任意一条命中规则或默认关闭的分组，不能被其他规则重新开启；
- 省略的 `capture` 默认为 `true`，省略的 `redact_fields` 默认为空；
- 路径匹配与 `exclude_paths` 同源：fnmatch 通配符、单次逐段解码、尾斜线处理、大小写跟随 `router.case_sensitive`、伪静态候选路径取并集，编码斜杠不会变成路径分隔符；
- `methods` 省略表示所有方法；填写时必须是非空列表，按大写比较；
- 未知配置键在启动时直接拒绝（避免拼写错误静默失效），修改后需重启服务。

## 内置敏感字段

以下字段名内置保护、始终参与匹配（无需配置，命中即脱敏为 `[REDACTED]`）：

| 类别 | 字段 |
| --- | --- |
| 通用凭据 | `password`、`passwd`、`pwd`、`secret`、`token`、`secret_key`、`ticket`、`otp` |
| 变体与确认字段 | `old_password`、`new_password`、`password_hash`、`confirm_password`、`password_confirm`、`db_password`、`user_password` |
| 认证头与令牌 | `authorization`、`x-authorization`、`cookie`、`set-cookie`、`api_key`、`x-api-key`、`access_token`、`refresh_token`、`auth_token`、`user_token`、`x-token`、`jwt_token` |
| 应用密钥 | `client_secret`、`app_secret` |
| 验证码与票据 | `sms_code`、`verify_code`、`verification_code`、`captcha`、`captcha_ticket`、`captcha_randstr`、`x-captcha-ticket`、`x-captcha-randstr`、`ticket_id` |

不再使用子串猜测——新增业务凭据字段（如 `id_card`、`bank_card`）需在对应方向与分组的 `redact_fields` 中显式配置完整名称。

## SQL 与绑定值

数据库操作明细默认只保留排查所需的最小信息：

| 配置项 | 默认 | 行为 |
| --- | --- | --- |
| `record_sql` | `false` | 默认仅记录 SQL 的 SHA-256 摘要（相同 SQL 可聚合对比）；开启后记录原文 |
| `record_bindings` | `false` | 默认隐藏全部绑定值；开启后仍对命名敏感参数（如 `:password`）脱敏 |

```php
// config/monitor.php
'record_sql' => false,      // SQL 字面量和注释可能含敏感信息，确认安全后再开启
'record_bindings' => false, // 位置绑定无法可靠推断敏感字段，默认全部隐藏
```

::: warning:两个开关相互独立
`record_sql` 与 `record_bindings` 互不影响。框架不使用正则猜测各数据库方言的字面量边界——开启 `record_sql` 意味着你确认 SQL 原文不含凭据类字面量。需要按字段名保护操作记录（如绑定参数名）时，配置 `operation.metadata.redact_fields`。
:::

## URI 与重定向脱敏

- 请求路径在采集前已完成单次逐段解码，`exclude_paths` 与 `privacy.rules` 的路径匹配使用同一匹配器，不会出现重复解码绕过；
- 重定向目标经 URI 脱敏器处理：仅保留协议、主机、端口与路径，**查询串、锚点与用户信息一律丢弃**（防止凭据经 Location 进入快照）；无法可靠解析的畸形地址记录为 `[INVALID_URI]`，实际跳转地址不受影响。

## 采集预算

预算的意义：单条慢请求快照的体积有硬上限，磁盘占用可预估，脱敏成本可控。

| 预算项 | 默认值 | 下限 | 超限行为 |
| --- | --- | --- | --- |
| `max_body_bytes` | 8192 | 0 | 正文超限后不输出原文，改为 `[BODY_LIMIT]` 占位或 `body_truncator` 生成的业务摘要 |
| `max_operations` | 200 | 0 | 后续操作不再记录明细，仅累加耗时与失败数到 `dropped_operations` |
| `max_snapshot_bytes` | 262144 | 16384 | 快照被裁剪并置 `snapshot_truncated = true` |

```php
// config/monitor.php
// 常规 JSON API 响应远小于 8KB，调低可减半每请求的正文累积内存与脱敏成本
'max_body_bytes' => 8192,
'max_operations' => 200,
// 请求快照总 JSON 字节预算（字节），最低 16 KiB
'max_snapshot_bytes' => 262144,
```

细节说明：

- **正文的实际上限是统一口径**：`min(max_body_bytes, max_snapshot_bytes / 4)`——除 `max_body_bytes` 外，还为快照总预算预留四分之一，防止大正文挤掉请求元数据与操作明细。请求正文、响应正文与超限摘要三条采集路径共用同一口径；
- `max_operations` 超限后统计不丢失——操作总次数、总耗时、失败数仍会进入 `operation_summary`，丢失的只是逐条明细；
- `max_snapshot_bytes` 包含固定结构与汇总预留，配置校验要求不低于 16384 字节；
- 分段写入（HTTP Chunk、SSE）的正文先累积，达到预算后拼接并统一脱敏，因此慢速流式响应的内存占用同样受预算约束；超限后立即释放缓存的原文（处理器提取摘要也发生在释放之后），后续分段仅累计字节数。

## 自定义正文裁剪

正文超限时默认输出 `[BODY_LIMIT]` 占位——只看得到字节数，看不到业务信息。如果超限正文中仍有值得保留的排查线索（如响应码与错误消息），可配置 `body_truncator` 处理器，从超限原文中提取一份**小的结构化摘要**进入快照：

```php
// config/monitor.php
// callable(string $body, array $context): ?array；仅超限时调用，返回待脱敏摘要
'body_truncator' => static function (string $body, array $context): ?array {
  // 不完整前缀或非 JSON 正文交给默认占位处理
  if (!$context['is_complete'] || $context['content_type'] !== 'application/json') {
    return null;
  }
  $decoded = json_decode($body, true, 512, JSON_THROW_ON_ERROR);
  // 只挑排查需要的字段，摘要应远小于 max_bytes
  return is_array($decoded) ? array_intersect_key($decoded, ['code' => true, 'message' => true]) : null;
},
```

### 处理器契约

| 要素 | 说明 |
| --- | --- |
| 签名 | `callable(string $body, array $context): ?array`，必须是 PHP callable，启动期校验 |
| 调用时机 | **仅正文超限时调用**，未超限正文照常走完整解析与脱敏流程 |
| `$body` | 超限时仍可取得的原文，**流式响应可能只有前缀**（`is_complete` 为 `false`） |
| `$context` | 见下表 |
| 返回值 | 待脱敏的数组摘要；`null` 表示使用默认占位 |

`$context` 字段：

| 字段 | 说明 |
| --- | --- |
| `path` | 请求路径（用于业务按接口定制摘要策略） |
| `method` | 请求方法；流式正文等无法确定时为空串 |
| `direction` | `request` 或 `response`，区分采集方向 |
| `content_type` | 正文类型，如 `application/json`、`application/x-www-form-urlencoded` |
| `is_complete` | 原文是否完整（分段发送中为 `false`） |
| `max_bytes` | 当前口径的正文上限，摘要应远小于该值 |

### 回退与失败行为

处理器不会让监控变脆弱，以下情况一律**整体回退为 `[BODY_LIMIT]` 占位**，不局部截断：

- 返回 `null` 或非数组值；
- 抛出任何异常（仅记录异常类名告警，不输出原始异常消息，避免业务凭据随解析错误进入日志）；
- 摘要**脱敏后**的实际字节仍超过 `max_bytes`——脱敏替换标记与编码开销可能使摘要膨胀，校验以脱敏后的真实体积为准。

### 隐私保证

- 对应方向与分组的 `capture => false` 时（如 `request.body` 或 `response.body` 关闭），正文**不采集、不解析，处理器也不会被调用**——既不向用户代码暴露原文，也不支付解析成本；
- 处理器返回的摘要随后会经过完整的脱敏流程（内置字段 + `defaults` + 命中 `rules` 的并集），处理器内部不需要自行处理敏感字段，但也不应依赖快照原样保留其返回值；
- 原始正文绝不直接进入快照：响应侧在调用处理器之前就已释放缓存原文，摘要提取失败也不遗留。

## 关闭采集

采集开关分为两级，**总开关关闭时分组配置无法重新开启**：

### 方向总开关

```php
// config/monitor.php
'capture_request' => false,  // 请求关闭时仅保留 method/path
'capture_response' => false, // 响应关闭时仍保留状态码、字节数和完成信息
```

### 分组级关闭

`privacy` 中将对应分组的 `capture` 设为 `false`，该分组整体不采集：

```php
// config/monitor.php
'privacy' => [
  'defaults' => [
    // 全局不采集请求正文（含 post 副本）
    'request' => ['body' => ['capture' => false]],
  ],
  'rules' => [
    // 仅某组接口不采集响应正文
    ['paths' => ['/admin/*'], 'response' => ['body' => ['capture' => false]]],
  ],
],
```

被关闭分组的输出：

- 正文类分组的 `content` 为 `[CAPTURE_DISABLED]`、`truncated` 为 `false`，但 `bytes` 等非内容元信息仍保留；
- DTO 状态为 `NOT_CAPTURED`，与字段脱敏的 `[REDACTED]`（状态 `REDACTED`）明确区分；
- 性能上同样有收益：`request.body.capture => false` 时甚至不会调用 `rawContent()` 读取原始正文。
