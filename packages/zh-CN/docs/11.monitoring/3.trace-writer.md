# 记录写入器与扩展点

慢请求监控把「采集」与「持久化」分离：采集层产出已脱敏、已有界的 `SlowRequestSnapshot`，持久化层只需实现一个单方法的 `TraceWriterInterface`。本文说明内置写入器、如何接入外部存储，以及缓存监控装饰器与 `TraceContext` 两个扩展点。

## TraceWriterInterface 契约

```php
namespace Viswoole\Monitor\Contract;

interface TraceWriterInterface
{
  /**
   * 写入一条慢请求记录
   */
  public function write(SlowRequestSnapshot $snapshot): void;
}
```

实现方需要了解的边界：

- **收到的快照已完成脱敏与限额**：无需（也不应）再做敏感信息处理；
- **写入发生在请求上下文清理之后**：实现内部的数据库、缓存、HTTP 调用不会被监控递归采集；
- **不可变 DTO**：`SlowRequestSnapshot` 及其嵌套对象全部为 readonly，可通过 `toArray()` 获取 JSON 安全的数组表示。

## 内置写入器：JsonTraceWriter

`Viswoole\Monitor\Writer\JsonTraceWriter` 基于框架文件日志（JSON 模式）实现，写入 `runtime/slow-requests` 目录：

```php
// config/monitor.php
'writer' => \Viswoole\Monitor\Writer\JsonTraceWriter::class,
```

复用文件日志的 JSON 编码（`JSON_UNESCAPED_UNICODE | JSON_UNESCAPED_SLASHES | JSON_INVALID_UTF8_SUBSTITUTE`）、按日分目录、轮转与过期清理机制；直接写入而非走协程缓冲，不依赖协程析构时机。

## 自定义写入器

### 方式一：配置类名

`writer` 填任意实现类的全限定名，框架通过容器解析实例（构造依赖自动注入），解析结果必须实现 `TraceWriterInterface`：

```php
// config/monitor.php
'writer' => \App\Monitor\ClickHouseTraceWriter::class,
```

```php
<?php
declare(strict_types=1);

namespace App\Monitor;

use Viswoole\Monitor\Contract\TraceWriterInterface;
use Viswoole\Monitor\Dto\SlowRequestSnapshot;

/**
 * 把慢请求快照投递到外部检索系统
 */
final class ClickHouseTraceWriter implements TraceWriterInterface
{
  public function __construct(private \ClickHouseDB\Client $client) {}

  public function write(SlowRequestSnapshot $snapshot): void
  {
    $this->client->insert('slow_requests', [$snapshot->toArray()]);
  }
}
```

### 方式二：服务提供者覆盖绑定

在服务提供者的 `register()` 中覆盖 `TraceWriterInterface` 绑定即可（容器传入实例时将其注册为单例），适合需要读取自身配置或组装复杂依赖的场景：

```php
use Viswoole\Monitor\Contract\TraceWriterInterface;
use Viswoole\Core\Service\Provider;

class MonitorProvider extends Provider
{
  public function register(): void
  {
    // 传入实例 = 注册为单例；也可传类名或闭包
    $this->app->bind(
      TraceWriterInterface::class,
      $this->app->make(ClickHouseTraceWriter::class)
    );
  }
}
```

两种方式的优先级：绑定为闭包形式后，应用覆盖的绑定优先生效。

## 缓存监控装饰器

启用监控后，`CacheManager` 注册的每个缓存商店都会被 `Viswoole\Cache\MonitoredDriver` 自动包装（跟随商店生命周期），缓存操作明细随之进入慢请求快照：

- 采集内容：商店名（store）、操作名（get/set/delete/...）、缓存键（含标签 tags）、结果摘要（命中/未命中、成功/失败与耗时）；
- **不采集缓存值**：只记录键与结果摘要，值本身永远不会进入快照；
- **零开销直通**：无请求上下文（定时器、任务进程、控制台命令）时装饰器直接透传，不分配任何采集结构；
- **语义不变**：保留原驱动的返回值与异常语义，业务代码无感知。

标签缓存（`MonitoredTag`）同样被包装，标签操作与受影响键的摘要会一并记录。缓存系统的使用方式见 [缓存使用](../6.cache/1.usage.md)。

## TraceContext：自定义采集点

业务代码中如果有值得计时的关键操作（外部 RPC、文件处理等），可通过 `TraceContext::measure` 把它登记为一条 `other` 类型操作，让慢请求快照完整还原请求时间线：

```php
use Viswoole\Monitor\TraceContext;

$result = TraceContext::measure(
  ['type' => 'other', 'name' => 'payment-gateway'], // 操作元数据
  fn (): array => $this->httpClient->post('/pay', $payload), // 原始操作
);
```

行为说明：

- **未启用监控时直接执行原操作**，不分配操作明细；
- 保持原操作的返回值与异常语义：失败记录异常类名后**原样抛出**，收尾错误不会把成功操作伪装成业务失败；
- 操作明细超限（`max_operations`）后仍累加耗时与失败统计到 `dropped_operations`。

另一个常用入口是获取当前请求的关联 ID：

```php
TraceContext::requestId(); // string|null，与快照和响应头一致
```
